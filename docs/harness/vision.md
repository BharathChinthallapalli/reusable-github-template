# Harness vision

Scope: the reusable development harness, not an application built with it.

Help an engineer turn a real user need into working, maintained software through
small, understandable changes. Preserve enough context and evidence for another
person or agent to continue across sessions without reconstructing the project
from chat history.

The intended experience is local-first: inspect the project, understand its
language, identify the next bounded outcome, implement it, verify it and leave a
useful handoff. Network services and deployment credentials enter only when the
selected task needs them. Azure and Microsoft 365 are the owner's delivery
priority; the reusable foundation remains independent of the application stack.

## What success looks like

- A new contributor can find the purpose, domain terms, current contracts,
  relevant commands and next action through short, maintained entrypoints.
- Smaller models receive explicit tasks and selective context. More capable
  models can investigate deeply within the same permissions and stopping rules.
- Deterministic checks handle repeatable validation; people retain consequential
  decisions, and agents supply implementation, analysis and review evidence.
- Several contributors can work in separate scopes and integrate changes without
  losing decisions, overwriting each other's work or inventing completed work.
- A representative project demonstrates the path from need to verified operation
  and a subsequent repair. A healthy template alone does not establish this.
