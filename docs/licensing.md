# Select a project license

This foundation contains original code and prose written for this deliverable.
External repositories were inspected for design patterns; their source code,
company policy text, logos, and license files are not bundled. Action
dependencies are referenced by commit and retain their own upstream licenses.

No default license is assigned to your future application. The repository owner
must choose an appropriate license or internal-use policy before distribution.
Do not reuse a company's copyright holder, vulnerability address, contributor
agreement, or conduct-policy enforcement contact from another template.

1. Decide whether this project is internal or intended for open-source sharing.
2. Add the organization's approved `LICENSE` text or an explicit internal-use
   policy, and update README.md.
3. Set `license_decision` in `template.json` to the chosen SPDX identifier or
   `internal-policy`, and record the policy location in docs/project.md.
4. Review dependency and asset licenses as part of adding them. Keep required
   notices. A root license does not replace third-party obligations.

The repository checker reports an unselected decision as a setup reminder; it
does not make legal determinations or assert that a license grants particular rights.

GitHub guidance: [Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
