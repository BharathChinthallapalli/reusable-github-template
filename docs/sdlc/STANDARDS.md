# Institutional standards routing

Canonical skill root stays .agents/skills. Skills guide work; they do not grant
tools, authenticate acceptance or override Guardian.

| Standard | Existing / added skill | Evidence output |
| --- | --- | --- |
| Security | security-review | Threat paths and tested boundaries |
| Compliance | compliance-mapping | Scoped matrix, source/date and owners |
| Data governance | data-governance + data-contracts | Data cards and boundary contracts |
| UX | ux-standards | Accessible journeys and verification |
| Brand | brand-standards | Supplied organization policy; missing source flagged |
| Eval design | ai-evaluation + test-design | Calibrated datasets, thresholds, regression cases |
| Azure/M365 conventions | azure-prepare, azure-validate, azure-deploy, tool-integration | Verified platform design and authorized release evidence |
| Cost modelling | cost-modelling | Explicit rate/workload assumptions and unit economics |
| Loop admission | sdlc-admission | Structural gates plus unresolved authority status |

Do not assume a skill discovered in one runtime has been loaded in another.
Existing metadata validation/catalog checks are not native runtime invocation tests.
