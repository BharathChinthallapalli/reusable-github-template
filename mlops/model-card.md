# Model card — one per exact model/version

## Identity and intended use
Provider, immutable version/deployment, owner, task, users, supported use and
excluded use; release/deprecation dates with official evidence.

## Data and training
Dataset/data-card versions and hashes, licensing, provenance, preprocessing,
training/fine-tune recipe, reproducibility limits and training/serving skew.

## Evaluation
Dataset/split hashes, comparator baseline, thresholds, grader calibration,
disaggregated quality/bias, adversarial/edge cases, error analysis, A/B result
where appropriate and limitations. Never fill missing outcomes with a pass.

## Safety, oversight and operations
Residual risks, abuse tests, human oversight, fallbacks, monitoring, cost,
promotion evidence, rollback and retirement.

Source pattern: [Mitchell et al., Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993).
This is an adapted project worksheet, not the paper's complete text.
